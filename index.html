College Viva & Project Explanation Guide

Key concepts and sample answers to help you explain this project with confidence during your viva examination.

1. What is the objective of this project?
This project is a Library Book Management System created to automate core library operations: cataloging books, tracking inventory (total vs. available copies), managing book issues and returns for students, and keeping an audit log of transactions.
2. What technologies are used, and why no heavy backend?
The project strictly uses fundamental web technologies:
  • HTML5: Defines semantic structure and interactive forms.
  • CSS3: Provides responsive layout (Flexbox/Grid), cards, tables, and clean color schemes.
  • JavaScript (Vanilla ES6): Handles application logic, DOM manipulation, form validation, and data management.
Instead of requiring a separate SQL/Node server, it utilizes the browser's native localStorage API, making the application zero-setup and runnable on any computer by simply opening index.html in any web browser.
3. How does localStorage work in this project?
localStorage is a web storage API that saves key-value pairs persistently in the user's browser across page reloads. Because localStorage only stores strings, we use:
  • JSON.stringify(array) when saving JavaScript objects to localStorage.
  • JSON.parse(string) when retrieving and reconstructing the JavaScript array upon page load.
We maintain two storage keys: college_library_books and college_library_transactions.
4. Explain the "Issue Book" business logic.
When a student issues a book:
  1. We check whether the chosen book exists and has availableCopies > 0. If it has 0 copies, the transaction is rejected with an error notice.
  2. If available, we decrement book.availableCopies by 1 and increment book.issuedCopies by 1.
  3. We create a new transaction record with a unique TXN-ID, student info, issue date, 14-day due date, and status "Issued".
  4. We write the updated state back to localStorage and re-render the dashboard, tables, and dropdowns.
5. Explain the "Return Book" business logic.
When a student returns a book:
  1. We locate the active transaction with status "Issued" matching the Student ID and Book ID.
  2. We increment book.availableCopies by 1 and decrement book.issuedCopies by 1.
  3. We update the transaction status to "Returned" and record the actual returnDate as today's date.
  4. We save the changes to localStorage and refresh all views.
6. How is real-time search implemented?
The search bar listens to the JavaScript input event. On every keystroke, it filters the books array using Array.prototype.filter() by comparing the lowercase query against the book's title, author, and ID. It then re-renders only the matching rows in the table.
